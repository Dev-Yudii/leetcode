# LeetCode Solutions
My personal LeetCode Daily Challenge solutions, one Python file per problem.

Files are generated by an external automation pipeline and solved here, in the open, one day at a time.


## Open challenges

[`PENDING.md`](./PENDING.md) is the index of what is waiting: every open challenge, when it was collected, how long it has been waiting and where its file is.

It is generated by the sync at the end of every run, so it is never stale. When it says a challenge is *not collected yet*, the cloud is late — not that there is nothing to do.

A solved file leaves the working tree: it stays in the repository, with its history, and the next open challenge takes its place.

## Completed challenges

[`COMPLETED.md`](./COMPLETED.md) is the other half of the index: every challenge that is already solved, when it was solved and how long it took from the moment the file reached this machine to the moment I marked it as done.

The links there are absolute, because a solved file is no longer in the working tree — the index points to where the file actually is, in the repository.


## Layout
Each solution file follows the same shape:

```python
"""
This problem was extracted on <YYYY-MM-DD HH:MM (UTC offset)> from LeetCode at <link>.
You can check the full problem description there.
Problem Title:
    ...
Difficulty:
    ...
Tags:
    ...
"""

class Solution:
    ...

if __name__ == "__main__":
    # the examples below come from the problem statement
    ...

"""
Notes:
    - ...
"""
# Add a line reading "# Solved" below when you finish the solution.
```

- Files live under the alphabetically first topic's folder as `{ID}_{slug}.py`. The folder is a filesystem rule only — it is not a classification of the problem.
- The header records when the problem was fetched and links back to the original statement — the full description lives on LeetCode, not here.
- Running the file executes the examples extracted from the problem statement. There is nothing to configure: the tests below are already written.
- `Notes:` at the bottom is where I leave thoughts from the solving session.
- The last line is the marker: `# Solved`. It closes the challenge.


## Solution Workflow
1. Open the file listed in [`PENDING.md`](./PENDING.md) — that is the challenge waiting for you.
2. Solve inside `class Solution`, running the local `__main__` tests as you go.
3. Do the full submission, with all test cases, on [LeetCode](https://leetcode.com).
4. Write your notes in the `Notes:` section.
5. Add a line reading `# Solved` at the end of the file. **That is all.**

Then the sync does the rest: it pushes the solution, closes the challenge in the ledger, records when it was solved and removes the file from the working tree.

> Do not delete the file and do not commit it by hand. The solution and its modification time disappear together, and the sync has nothing left to push. Mark it and leave it there.

The marker must be a line of its own: `# Solved` works, `#solved` and `# --solved` work too, but `# Solved took two hours` does not — a line with anything else on it is not the marker. Put extra notes in the `Notes:` section.
